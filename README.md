# TA รถโม่ — Dashboard คะแนนวันทำงานและรางวัล

Dashboard สรุปคะแนนวันทำงานของรถโม่ (truck_no) การคำนวณเงินรางวัล/การันตี
และการตัดเงินรางวัลของ จบส. (driver_no)

## มีแค่ 2 ไฟล์

```
index.html          หน้า Dashboard ทั้งหมด (รวมตัวอ่าน Excel และตรรกะคำนวณไว้ในไฟล์เดียว)
TA100.xlsx          ฐานข้อมูล
TA100.json          ผลคำนวณสำเร็จรูป (ไม่บังคับ แต่ทำให้เปิดเร็วขึ้นมาก — ดูหัวข้อด้านล่าง)
```

`index.html` ต้องอยู่ **ชั้นบนสุดของ repo** ส่วนไฟล์ Excel วางได้ทั้งที่
**ชั้นบนสุด** (`TA100.xlsx`) หรือ **ในโฟลเดอร์ data** (`data/TA100.xlsx`)
หน้าเว็บจะหาให้เองทั้งสองที่ ชื่อไฟล์ต้องเป็น `TA100.xlsx` ตรงตัวพิมพ์ใหญ่เล็ก

ไม่ต้องมีโฟลเดอร์ `vendor` หรือไฟล์ `engine.js` / `worker.js` อีกแล้ว

## อัปเดตข้อมูลเดือนใหม่

แทนที่ไฟล์ `TA100.xlsx` ด้วยไฟล์เดือนใหม่ แล้ว commit — จบ

ผ่านหน้าเว็บ GitHub: **Add file → Upload files** →
ลากไฟล์ชื่อ `TA100.xlsx` ทับของเดิม → Commit changes

หน้าเว็บอ่าน **เดือน/ปีจากคอลัมน์ `work_date` ในชีต Punch** เอง และดึงจำนวนวันทำงาน
จากชีต `วันทำงาน` ให้อัตโนมัติ — ไม่ต้องแก้อะไรในโค้ด

> ก่อนอัปขึ้น GitHub ทดลองได้ด้วยปุ่ม **“ใช้ไฟล์ Excel อื่น”** มุมขวาบน
> เลือกไฟล์จากเครื่องแล้วดูผลได้ทันทีโดยไม่ต้อง commit

ชีตที่ต้องมีในไฟล์ Excel: `Punch`, `จดทะเบียน`, `การันตี`, `เวลาทำงาน`,
`วันทำงาน`, `คะแนน-Punch`, `ค่าบริหารความพร้อม` — ถ้าขาดชีตไหน หน้าเว็บจะบอกชื่อชีตที่หายไป

ผ่าน `file://` ให้รันเซิร์ฟเวอร์เล็ก ๆ แทน


หรือกดปุ่ม **“เลือกไฟล์ Excel จากเครื่อง”** ในกล่องแจ้งเตือน ก็ใช้งานได้เหมือนกัน

## ทำให้เปิดเร็วขึ้น 10 เท่า (ไม่บังคับ แต่แนะนำมาก)

ชีต Punch เป็น XML ขนาด 64 MB ตอนคลายซิป การให้เบราว์เซอร์แกะไฟล์ทุกครั้ง
ใช้เวลา 5–15 วินาที (ขึ้นกับเครื่อง) วิธีเลี่ยงคือเก็บ **ผลคำนวณสำเร็จรูป**
ไว้ใน repo ด้วย

1. เปิด Dashboard รอให้คำนวณเสร็จ (ครั้งนี้ช้าครั้งเดียว)
2. กดปุ่ม **“บันทึก TA100.json”** มุมขวาบน จะได้ไฟล์ `TA100.json`
3. อัปไฟล์นี้ขึ้น repo ไว้ที่เดียวกับ `TA100.xlsx`

หลังจากนั้นทุกคนที่เปิด Dashboard จะได้ข้อมูลภายใน **1–2 วินาที**

หน้าเว็บจะเทียบขนาดไฟล์ Excel กับที่บันทึกไว้ใน `TA100.json` เสมอ
ถ้าอัป Excel เดือนใหม่แล้วยังไม่ได้อัป JSON ใหม่ ระบบจะรู้ว่าไม่ตรงกัน
แล้วกลับไปคำนวณจาก Excel ให้เอง — ข้อมูลไม่มีทางเก่าค้าง

> ทำ 3 ขั้นตอนนี้ซ้ำทุกครั้งที่อัป Excel เดือนใหม่ ถ้าไม่ทำก็ยังใช้งานได้ปกติ
> แค่เปิดช้าลง

## เรื่องความเร็ว

ไฟล์ Excel ~10 MB มี 53,000 กว่าแถว (ชีต Punch คลายซิปแล้วเป็น XML ขนาด 64 MB)
เปิดครั้งแรกใช้เวลาประมาณ 5–10 วินาทีหลังดาวน์โหลดเสร็จ มีแถบแสดงความคืบหน้าบอกทุกขั้น
หลังจากนั้นผลคำนวณจะถูกจำไว้ใน IndexedDB ของเบราว์เซอร์ เปิดครั้งต่อไปขึ้นภายใน 1 วินาที

ถ้าอยากให้เร็วขึ้นอีก ลดขนาดไฟล์ Excel ได้โดยลบชีตที่ไม่ได้ใช้ ลบรูปภาพในไฟล์
และเก็บเฉพาะคอลัมน์ที่จำเป็นในชีต Punch

หน้าเว็บเช็ค ETag ของไฟล์ Excel ทุกครั้งที่เปิด ถ้าไฟล์ใน GitHub เปลี่ยน
จะคำนวณใหม่ให้เองโดยอัตโนมัติ ถ้าอยากบังคับคำนวณใหม่กดปุ่ม **“โหลดข้อมูลใหม่”**

การคำนวณทำใน Web Worker เพื่อไม่ให้หน้าเว็บค้าง ถ้าเบราว์เซอร์ไม่รองรับ
จะสลับไปคำนวณบนเธรดหลักให้อัตโนมัติ

> การ commit ไฟล์ 10 MB ทุกเดือนจะทำให้ repo โตเดือนละ ~10 MB
> ถ้าสะสมนานจนใหญ่เกินไป ค่อยพิจารณาใช้ Git LFS หรือเก็บไฟล์ย้อนหลังไว้ที่อื่น

## แท็บในหน้าเว็บ

| แท็บ | เนื้อหา |
|---|---|
| ภาพรวม | KPI, การกระจายกลุ่ม TA, กลุ่ม TA แยกรายกิจการ, เงินรางวัลรายผู้รับเหมา, สรุปตามกิจการ, 15 คันที่ %TA ต่ำสุด |
| คะแนนรายวัน | ตาราง รถ × วันที่ 1–31 พร้อมสังกัด (กิจการ/ภาค/แผนก/โรงงาน/ผู้รับเหมา) |
| คำนวณรางวัล | คะแนนรวม, คิว, รายได้, %TA, กลุ่ม TA, เงินรางวัล, การันตี, รางวัลสุทธิ |
| หักเงิน จบส. | ตาราง คนขับ × วันที่ พร้อมยอดรวมที่ถูกหัก — วางเมาส์ที่ช่องที่มีสามเหลี่ยมเพื่อดูสาเหตุ |
| รายละเอียด Punch | รายรายการ พร้อม punch_in_time / punch_out_time และยอดหักแยกตามสาเหตุ |
| เกณฑ์คะแนน | ตารางเกณฑ์ทั้งหมดที่ระบบใช้ |

ทุกแท็บมีตัวกรอง **เดือนเริ่มต้น – เดือนสิ้นสุด** และตัวกรองลดหลั่น
กิจการ → ภาค → แผนก → โรงงาน → ผู้รับเหมา พร้อมกรองกลุ่ม TA,
ค้นหาเบอร์รถ/คนขับ และปุ่ม **บันทึก Excel**

ไฟล์ที่บันทึกออกมาเป็น `.xlsx` จริง มีสีเหมือนบนหน้าเว็บ (สีคะแนน สีกลุ่ม TA
สีของยอดที่ถูกหัก) ตีเส้นตารางทุกช่องตามจำนวนข้อมูลที่มี ตั้งความกว้างคอลัมน์
และเปิด AutoFilter ที่หัวตารางให้แล้ว ช่อง `truck_no` และ `driver_no`
บันทึกเป็นข้อความเสมอ เลข 0 นำหน้าจึงไม่หาย (เช่น `0018` ไม่กลายเป็น `18`)

ช่องที่มีหมายเหตุบนหน้าเว็บจะกลายเป็น **Comment ของ Excel** วางเมาส์ในไฟล์
แล้วขึ้นข้อความเดียวกับที่เห็นบน dashboard — ช่องคะแนนที่ถูกหัก, ช่องยอดหักเงิน จบส.
และช่องอัตราเงินรางวัลของรถที่ถูกตัดสิทธิ์

> แท็บคะแนนรายวันมี comment ประมาณ 26,000 ช่อง ไฟล์จึงใหญ่ราว 5 MB
> และใช้เวลาสร้างสักครู่ (มีแถบความคืบหน้าแสดงระหว่างสร้าง)

## ช่วงเดือน

หน้าเว็บอ่านเดือนจากคอลัมน์ `work_date` ในชีต Punch ถ้าไฟล์มีหลายเดือน
ช่องเลือกเดือนจะมีให้เลือกครบทุกเดือน และเลือกเป็นช่วงได้

เมื่อเลือกช่วงมากกว่า 1 เดือน ระบบจะ

- รวมคะแนนและคิวของทุกเดือนในช่วง แล้วคิด %TA จาก **วันทำงานรวม** ของช่วงนั้น
- รวมฐานการันตีของทุกเดือนในช่วง แล้วคูณ %การันตีตามกลุ่ม TA ที่ได้
- ตารางคะแนนรายวันจะมีหัวตาราง 2 ชั้น บอกว่าคอลัมน์ไหนเป็นของเดือนอะไร

ถ้าไฟล์มีเดือนเดียว ช่องเลือกเดือนจะแสดงเดือนนั้นเดือนเดียวและถูกปิดไว้
ผลลัพธ์เหมือนเดิมทุกประการ

> วิธีดูข้อมูลย้อนหลังหลายเดือน: เอาแถว Punch ของเดือนก่อน ๆ ต่อท้ายในชีตเดียวกัน
> และเพิ่มแถวของเดือนนั้นในชีต `วันทำงาน` / `การันตี` / `จดทะเบียน`
> (ชีตเหล่านี้มีคอลัมน์ ปี/เดือน อยู่แล้ว ระบบจะจับคู่ให้เอง)

## วิธีคิดคะแนน

คะแนนตั้งต้น **1 คะแนน/วัน/คัน** แล้วหักตามเหตุการณ์ หักได้ไม่เกิน 1 และได้ไม่เกิน 1

| หักจาก | เกณฑ์ |
|---|---|
| `punch_in_status` | มาสาย (T) = −0.25 |
| `device_in` | Punch in ผ่าน Web ไม่ใช้ SDA (W) = −0.25 |
| `punch_out_status` | ตามชีต `คะแนน-Punch` เช่น รถเสีย = −0.5, หนีงาน/ว่าง = −1 |
| `check_time` | ไม่ตรวจรถทั้งวัน (ช่องว่าง) = −1 · ตรวจรถสาย = −0.25 |

**มาสาย กับ ตรวจรถสาย หักได้อย่างใดอย่างหนึ่งเท่านั้น**

- `punch_in_status = T` (มาสาย) → หัก 0.25 เรื่องมาสายอย่างเดียว ไม่นำเรื่องตรวจรถสายมาหักซ้ำ
- `punch_in_status = O` (ปกติ) → เช็กว่า `check_time` ไม่เกิน
  **เวลาเข้างานโรงงาน (ชีต `เวลาทำงาน`) + 30 นาที** ถ้าเกินหัก 0.25 (เทียบระดับนาที)

กรณีไม่ตรวจรถทั้งวัน (ช่อง `check_time` ว่าง) หัก 1 คะแนนเสมอ ไม่ว่า `punch_in_status`
จะเป็น T หรือ O

### กรณี `device_out = W` (ไม่ใช้ SDA ตอน Punch out) และ `punch_out_status = O`

| `punch_out_adj_remark` | `punch_out_time` | ผล |
|---|---|---|
| “ระบบคำนวณ” | หลังเวลาเลิกงาน | ไม่หัก |
| “ระบบคำนวณ” | ก่อนเวลาเลิกงาน | หัก 1 — กลับก่อนเลิกงาน |
| ว่าง / เคาะ / จุด / ขีด / “ปกติ” | ก่อนเวลาเลิกงาน | หัก 0.25 |
| ว่าง / เคาะ / จุด / ขีด / “ปกติ” | หลังเวลาเลิกงาน | ไม่หัก |
| ระบุเหตุผลอื่น | ไม่เกี่ยว | ไม่หัก |

เวลาเลิกงานอ่านจากชีต `เวลาทำงาน` คอลัมน์ `OUT`

ถ้า `punch_out_status` ไม่ใช่ O (ไม่ว่า `device_out` จะเป็น M หรือ W)
ให้หักตามรหัสในชีต `คะแนน-Punch` ตามปกติ

### กรณีโรงงานขอแก้ไข — ได้เต็ม 1 คะแนน

ถ้าฝั่ง Punch in **หรือ** Punch out ฝั่งใดฝั่งหนึ่งเข้าเงื่อนไขครบทุกข้อ ถือว่าโรงงานขอแก้ไข
วันนั้นได้ 1 คะแนนเต็ม ไม่หักอะไรเลย แม้ช่อง `check_time` จะว่าง (ไม่ได้ตรวจรถ)

| เงื่อนไข | ค่าที่ต้องเป็น |
|---|---|
| `device_in` / `device_out` | `W` หรือว่าง |
| `punch_in_time` / `punch_out_time` | `00:00` |
| `punch_in_status` / `punch_out_status` | `O` |
| `punch_in_adj_remark` / `punch_out_adj_remark` | ระบุเหตุผลไว้ ต้องไม่ใช่ “ระบบคำนวณ” และไม่ใช่การเคาะ จุด ขีด หรือ “ปกติ” |

ตัวอย่างเหตุผลที่พบในข้อมูล: วันหยุดประเพณี, วันแม่, รง.หยุด, วันเฉลิมพระชนมพรรษา

### กฎที่ดูจากข้อความในช่อง `punch_out_adj_remark`

แถวในชีต `คะแนน-Punch` ที่ช่อง `In/Out` เป็น **`punch_out_adj_remark`**
จะถูกใช้เป็นคำค้น — ถ้าข้อความในช่องหมายเหตุของแถว Punch มีคำนั้นอยู่
จะคิดคะแนนรถและค่าปรับ จบส. ตามที่ระบุในแถวนั้น

| ความหมายจากระบบ | คำค้นที่ใช้ | ผล |
|---|---|---|
| ไม่ให้ความร่วมมือ | ไม่ให้ความร่วมมือ | หัก จบส. 50 บาท ในวันนั้น |
| ข้อร้องเรียน จบส.เป็นฝ่ายผิด (เพิ่ม) | ข้อร้องเรียน | ตัดทั้งโครงการ (เงินรางวัล บาท/คิว = 0) |

คำค้นคือ **คำแรก** ของช่องความหมายจากระบบ (ตัดวงเล็บออกแล้ว)
เพิ่มหรือแก้กฎได้ในไฟล์ Excel โดยไม่ต้องแก้โค้ด

### การตัดสิทธิ์เงินรางวัล บาท/คิว

รถที่มี `punch_out_status` = **J** (ตรวจพบสารเสพติด) หรือ **K** (ตรวจพบแอลกอฮอล์ > 0 mg%)
หรือมีข้อความ **“ข้อร้องเรียน”** ใน `punch_out_adj_remark` แม้วันเดียวในเดือนนั้น
→ อัตราเงินรางวัลเป็น 0 บาท/คิว แต่ยังมีสิทธิ์ได้เงินการันตีตามปกติ

### ค่าบริหารความพร้อม

รถกลุ่ม **TA 1 / TA 2 / TA 3** ได้ค่าบริหารความพร้อมตามจำนวนเงินในชีต
`ค่าบริหารความพร้อม` ช่อง “ค่าบริหารความพร้อม (บาท)” เฉพาะโรงงานที่ช่อง `Status` เป็น `Open`

`รางวัลสุทธิ` = เงินรางวัล + ส่วนต่างการันตี + ค่าบริหารความพร้อม

ถ้า driver_no หนึ่งคน Punch รถเกิน 1 คันในวันเดียวกัน จะคิดคะแนนแยกตามเกณฑ์ของ
รถแต่ละคัน และกำกับหมายเหตุ “Driver Punch N คัน” ไว้ที่ช่องคะแนนของวันนั้น

## การคำนวณรางวัล

| กลุ่ม | %TA | เงินรางวัล | การันตี |
|---|---|---|---|
| TA 1 | > 95% | 6 บาท/คิว | 100% |
| TA 2 | ≥ 90% | 4 บาท/คิว | 96.5% |
| TA 3 | ≥ 85% | 2 บาท/คิว | 93% |
| TA 4 | ≥ 75% | — | — |
| TA 5 | ≥ 50% | −3 บาท/คิว | — |
| TA 6 | < 50% | −6 บาท/คิว | — |

- `%TA` = คะแนนรวมทั้งเดือน ÷ วันทำงานของเดือน
- `เงินรางวัล` = อัตราตามกลุ่ม × คิวรวม (`dp_dispatch_qty`)
- `ยอดการันตี` = ฐานการันตี × %การันตีตามกลุ่ม
- `ฐานการันตี` ใช้ช่อง **T012** เฉพาะรถที่ `FLEET_TYPE_NO = T012`
  และวันหมดอายุ GT รถใหม่ยังไม่พ้นเดือนที่สรุป — นอกนั้นใช้ช่องการันตีรถเก่า
- `ส่วนต่างการันตี` = ยอดการันตี − รายได้ค่าขนส่งจริง (`partialtcost`) ถ้าติดลบนับเป็น 0
- `รางวัลสุทธิ` = เงินรางวัล + ส่วนต่างการันตี + ค่าบริหารความพร้อม

## การตัดเงินรางวัล จบส.

ดูรหัส `punch_out_status` ของ driver_no รายวัน แล้วแทนค่าด้วยช่อง
`หัก จบส.(บาท)` จากชีต `คะแนน-Punch` (P = 50, R = 100, 9 = 50, E = 100)
รหัสที่ระบุว่า “ตัดทั้งโครงการ” (J, K) ไม่คิดเป็นตัวเงินรายวัน
แต่จะขึ้นหมายเหตุไว้ในแท็บรายละเอียด

## ปรับแต่งเกณฑ์

เกณฑ์คะแนนรายรหัส (O, T, A, B, …) และค่าปรับ จบส. อ่านจากชีต `คะแนน-Punch`
ในไฟล์ Excel โดยตรง — แก้ในไฟล์ Excel ได้เลยไม่ต้องแตะโค้ด

ส่วนเกณฑ์กลุ่ม TA และค่าคงที่ อยู่ใน `index.html` ในบล็อก `<script id="libsrc">`
ค้นหาคำว่า `TA_TIERS`

```js
var TA_TIERS       = [...];  // เกณฑ์ %TA, อัตราเงินรางวัล, %การันตี
var LATE_GRACE_MIN = 30;     // นาทีผ่อนผันหลังเวลาเข้างาน (ใช้เมื่อ punch_in = O)
```

แก้แล้วให้เพิ่มเลข `APP_VERSION` (อยู่ต้นบล็อก `<script>` หลัก) ขึ้น 1
เพื่อให้เบราว์เซอร์ทิ้งผลคำนวณเก่าที่จำไว้
